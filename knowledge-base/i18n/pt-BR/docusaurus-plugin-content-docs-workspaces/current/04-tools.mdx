O workspace Tools fornece a espinha dorsal de automação para o projeto Elo Orgânico. Ele centraliza servidores especializados de Model Context Protocol (MCP) e scripts de infraestrutura projetados para aumentar a produtividade dos desenvolvedores, garantir a paridade de ambiente por meio de compilações Docker multi-stage e permitir fluxos de trabalho de engenharia AI-native seguros e de alto contexto.

    ### Ecossistema Model Context Protocol (MCP)

    O monorepo Elo Orgânico apresenta um ecossistema MCP especializado e conteinerizado. Ele expõe capacidades de desenvolvimento estruturadas e contextos da base de código para clientes LLM (como o Antigravity CLI ou agentes externos) por meio de uma rede de gateway segura e de alto desempenho.

    #### Arquitetura de Gateway Federado Unificado

    Para evitar o acúmulo de conexões e gerenciar a segurança, o gateway (`elo-mcp-gateway`) é construído como um **Servidor MCP Federado** utilizando a biblioteca oficial `@modelcontextprotocol/sdk`.

    *   **Conexão Única:** Clientes LLM estabelecem uma única conexão com o gateway via Server-Sent Events (SSE). O gateway agrega todas as ferramentas dos servidores upstream de forma dinâmica.
    *   **Namespaces Dinâmicos de Ferramentas:** As ferramentas dos servidores upstream são prefixadas com o namespace do container correspondente (ex: `github__search_repositories`, `context7__query-docs`) para evitar colisões de nomes.
    *   **Injeção de Contexto no Handshake:** O gateway lê todos os arquivos markdown de contexto no diretório `context/`, compila-os durante a inicialização e os injeta no campo `result.instructions` da resposta do handshake de inicialização. O cliente LLM inclui automaticamente essas diretrizes em suas instruções de sistema ao interagir com o servidor.

    #### Roteamento via Sockets TCP Puros (`socat`)

    Para garantir máxima eficiência e latência ultra-baixa, o gateway se comunica com os containers upstream por meio de **sockets TCP puros** usando uma implementação personalizada de `TCPClientTransport`.

    Os containers upstream não executam servidores Node.js ou adaptadores Fastify customizados. Em vez disso, rodam um utilitário leve em C chamado `socat` que conecta conexões TCP de entrada diretamente ao fluxo stdio do binário MCP subjacente.

    ### Agentes de IA Conteinerizados

    O workspace `tools/agents` provisiona as CLIs do GitHub Copilot e do Google Antigravity como serviços Docker de longa execução. Isso elimina as instalações manuais de CLI nas máquinas host dos desenvolvedores e garante a paridade de ambiente entre estações de trabalho locais e VMs na nuvem.

    #### Visão Geral da Arquitetura

    Os containers de agentes rodam dentro da mesma rede bridge `elo-mcp-net` que o gateway MCP, comunicando-se com ele através de roteamento DNS interno. Nenhuma exposição de porta a nível de host é necessária para a comunicação entre serviços.

    ```mermaid
    graph TD
      direction TD
      subgraph "Host Machine"
        Dev["Developer (VS Code / Terminal)"]
      end

      subgraph "Docker: elo-agents"
        Copilot["agent-copilot"]
        Antigravity["agent-antigravity"]
      end

      subgraph "Docker: elo-mcp"
        Gateway["elo-mcp-gateway (elo.internal.tools:3000)"]
        Github["elo-mcp-github"]
        Context7["elo-mcp-context7"]
        Browser["elo-mcp-browser"]
        Dockerhub["elo-mcp-dockerhub"]
      end

      Dev -- "docker exec -it" --> Copilot
      Dev -- "docker exec -it" --> Antigravity
      Copilot -- "elo-mcp-net" --> Gateway
      Antigravity -- "elo-mcp-net" --> Gateway
      Gateway -- "TCP: 3001" --> Github
      Gateway -- "TCP: 3002" --> Context7
      Gateway -- "TCP: 3003" --> Browser
      Gateway -- "TCP: 3004" --> Dockerhub
    ```

    #### Estrutura de Diretórios

    ```
    tools/agents/
    ├── .env.agents.example     # Modelo de variáveis de ambiente (rastreado)
    ├── .env.agents             # Segredos (ignorado pelo Git)
    ├── compose.yaml            # Orquestração para ambos os containers de agentes
    ├── mcp_config.json         # Configuração MCP unificada (injetada nos containers)
    ├── skills/                 # Skills compartilhadas de agentes (injetadas nos containers)
    │   ├── code-expert/
    │   └── doc-expert/
    ├── copilot/
    │   ├── Dockerfile          # GitHub CLI + Copilot CLI + Docker CLI
    │   ├── data/               # Ignorado pelo Git: estado de sessão e tokens do Copilot
    │   └── gh-config/          # Ignorado pelo Git: credenciais e extensões do GitHub CLI
    └── antigravity/
        ├── Dockerfile          # Antigravity CLI + Docker CLI
        ├── data/               # Ignorado pelo Git: conversas, brain, logs de runtime
        ├── settings.json       # Configurações TUI controladas por versão (caminhos internos)
        ├── statusline.sh       # Script da barra de status da CLI
        └── title.sh            # Script do título da janela da CLI
    ```

    #### Estratégia de Injeção de Configuração

    Toda a configuração é injetada via volumes bind-mount na inicialização dos containers. Nenhum arquivo é embutido diretamente nas camadas de imagem, assegurando que alterações entrem em vigor sem a necessidade de reconstruções.

    | Origem no Host | Destino no Container | Propósito |
    | :--- | :--- | :--- |
    | `../../` | `/workspace` | Diretório de trabalho completo do monorepo |
    | `./skills/` | `/workspace/.agents/skills` | Skills compartilhadas visíveis para ambas as CLIs |
    | `./mcp_config.json` | `/workspace/.agents/mcp_config.json` | Configuração unificada do endpoint do Gateway |
    | `./antigravity/data/` | `/root/.gemini/antigravity-cli/` | Persistência de dados de runtime do Antigravity |
    | `./antigravity/settings.json` | `/root/.gemini/antigravity-cli/settings.json` | Configurações TUI controladas por versão |
    | `./copilot/data/` | `/root/.copilot/` | Estado de sessão persistente do Copilot |
    | `./copilot/gh-config/` | `/root/.config/gh/` | Credenciais persistentes do GitHub CLI |
    | `/var/run/docker.sock` | `/var/run/docker.sock` | Orquestração de Docker-out-of-Docker |
    | `~/.ssh` | `/root/.ssh` (somente leitura) | Chaves SSH do host para operações Git |
    | `~/.gitconfig` | `/root/.gitconfig` (somente leitura) | Identidade Git do host |

    #### Conectividade de Rede MCP

    Dentro dos containers de agentes, o Gateway MCP Federado é resolvido através do alias da rede Docker `elo.internal.tools` na porta `3000`:

    ```json
    {
      "mcpServers": {
        "elo-mcp-gateway": {
          "url": "http://elo.internal.tools:3000/sse",
          "lifecycle": "eager"
        }
      }
    }
    ```

    :::caution Requisito de Sequência de Inicialização
    A stack do MCP deve estar em execução antes que a stack dos agentes seja iniciada. A rede bridge `elo-mcp-net` é criada e pertencente ao compose em `tools/mcp/compose.yaml`. Iniciar os agentes antes do MCP resultará em erro de resolução de rede.

    1. `pnpm mcp:up`
    2. `pnpm agents:up`
    :::

    #### Comandos de Ciclo de Vida

    | Comando | Ação |
    | :--- | :--- |
    | `pnpm agents:up` | Constrói as imagens (se necessário) e inicia ambos os containers de agentes em background. |
    | `pnpm agents:down` | Para e remove os containers de agentes. |
    | `pnpm agents:reset` | Limpeza profunda com remoção de volumes, seguida por reconstrução e reinicialização. |
    | `pnpm antigravity:auth` | Executa o fluxo de autenticação do Google OAuth no terminal ativo. |
    | `pnpm copilot:auth` | Executa o fluxo de autenticação do GitHub OAuth no terminal ativo. |

    #### Integração de Tarefas do VS Code

    As CLIs de agentes são invocadas via tarefas `docker exec` registradas em `.vscode/tasks.json`. As tarefas são rotuladas com os prefixos `[Docker]` ou `[Host]` para distinguir a execução conteinerizada da instalação global no host.

    | Rótulo da Tarefa | Destino da Execução |
    | :--- | :--- |
    | `[Docker] Antigravity CLI` | `docker exec -it agent-antigravity agy` |
    | `[Docker] Copilot CLI` | `docker exec -it agent-copilot copilot` |
    | `[Host] Antigravity CLI` | Instalação global do `agy` no host |
    | `[Host] Copilot CLI` | Instalação global do `copilot` no host |

    #### Autenticação e Persistência de Sessão

    Ambas as CLIs usam autenticação via fluxo de dispositivos OAuth. Para autenticar os agentes conteinerizados, execute os scripts de autenticação direta (`pnpm copilot:auth` ou `pnpm antigravity:auth`) no terminal. A CLI exibirá uma URL e um código de verificação. O desenvolvedor abre a URL no navegador do host, realiza o login, e os tokens gerados são gravados diretamente no diretório do container.

    ##### Armazenamento Persistente & Arquitetura sem Reconstruções

    Como os diretórios de credenciais são montados (bind-mount) no host:
    *   `agent-copilot` monta `./copilot/data/` em `/root/.copilot/` e `./copilot/gh-config/` em `/root/.config/gh/`
    *   `agent-antigravity` monta `./antigravity/data/` em `/root/.gemini/antigravity-cli/`

    Qualquer token de autenticação gerado é gravado diretamente nesses diretórios em tempo real. Assim:
    *   **Nenhuma reconstrução de container é necessária:** Reiniciar o container não apaga as credenciais, pois elas são lidas dinamicamente do volume.
    *   **Isolamento do Host:** As credenciais de dentro do container não interferem com as pastas globais do desenvolvedor no host (ex: `~/.gemini` ou `~/.config/gh`).
    *   **Acesso Sincronizado Automático:** Concluída a autenticação, os acessos entram em vigor imediatamente, sem cópias manuais ou reinicializações.

    :::note
    Os diretórios `data/` e `gh-config/` estão no `.gitignore`. Eles existem apenas na máquina local do desenvolvedor e nunca são enviados ao repositório Git.
    :::

    ### Infraestrutura Isolada e Roteamento de Rede

    A segurança e previsibilidade do ambiente são mantidas através de uma rede bridge Docker isolada e nomeada (`elo-mcp-net`), evitando acessos externos indesejados.

    #### Configuração de Gateway & Roteamento

    *   **Servidor de Gateway Unificado:** Um servidor MCP customizado baseado em Fastify (`elo-mcp-gateway`) executando sob Node.js serve como porta de entrada. Ele expõe a porta `3005` para a máquina host e escuta na porta `3000` internamente.
    *   **Isolamento de Segurança Estrito:** O gateway é o **único** container a mapear portas para a máquina host. Os servidores MCP internos **não possuem nenhuma porta exposta publicamente** no `compose.yaml`, inviabilizando varreduras de conexões diretas a partir da máquina host ou internet pública.
    *   **Pontes TCP Internas:** Na rede bridge `elo-mcp-net`, o gateway se comunica com os servidores internos por meio de sockets TCP puros nas portas de `3001` a `3004`. O gateway é resolvido internamente usando o alias `elo.internal.tools`.
    *   **Conexão Host-para-Container:** Clientes locais de desenvolvimento (como a CLI global do Google Antigravity rodando no host) se comunicam com o gateway através da interface loopback do host usando:
        ```
        http://localhost:3005/sse
        ```

    ### Regras de Engajamento para Agentes de IA

    O workspace define diretrizes estritas para agentes através de arquivos estruturados de contexto. Essas regras garantem que as alterações automatizadas sigam os padrões de arquitetura e qualidade do projeto.

    #### Convenções Operacionais

    *   **Domain Core First:** Alterações em esquemas compartilhados ou modelos de dados devem originar-se nos pacotes `core` (Single Source of Truth) antes de se propagarem pelas aplicações.
    *   **Tipagem e Lints Estritos:** Os agentes são estritamente proibidos de usar `any` ou ignorar as configurações do TypeScript/ESLint. A validação via `typecheck` é obrigatória após qualquer alteração de código.
    *   **Minimalismo Tecnológico:** Evite sugerir dependências externas a menos que não haja solução nativa ou implementada na stack existente (Fastify, React, Zustand, Zod).
    *   **Documentação Convencional:** Atualizações na documentação devem adotar tom profissional, técnico e objetivo, utilizando recursos do MDX (como Tabs) para gerenciar informações densas.
  </TabItem>

    | Comando | Ação de Engenharia |
    | :--- | :--- |
    | `pnpm mcp:up` | Inicializa todo o ambiente do gateway federado e servidores MCP. |
    | `pnpm mcp:down` | Finaliza e remove a stack do gateway e containers MCP. |
    | `pnpm mcp:reset` | Limpeza agressiva da stack (volumes removidos) seguida de reconstrução completa. |

    #### Organização do Workspace

    *   `tools/mcp/compose.yaml`: Define os serviços, dependências, volumes e redes dos containers.
    *   `tools/mcp/gateway/`: Contém o servidor de Gateway Fastify Federado (`server.ts` e seu Dockerfile).
    *   `tools/mcp/infrastructure/`: Contém os Dockerfiles dos servidores upstream.
    *   `tools/mcp/context/`: Armazena diretrizes de contexto organizadas por subdiretório para cada MCP (ex: `github/instructions.md`, `browser/instructions.md`).
    *   `tools/mcp/config/`: Gerencia arquivos de variáveis de ambiente e segredos de cada MCP.
    *   `tools/scripts/`: Utilitários TypeScript para geração de roadmaps e changelogs (`generate-roadmap.ts`, `generate-changelog.ts`).
